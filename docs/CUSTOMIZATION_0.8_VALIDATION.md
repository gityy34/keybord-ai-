# 0.8.0 keyboard customization validation

The existing IME remains the app entry point. `KeyboardView` keeps the typing surface and More panel in the current app; `ToolOrder` persists one ordered membership list for the toolbar and one for More. More remains visible at the right edge while the toolbar scrolls. Each tool retains its existing command route. Long-press a tile for Reorder or to move it between areas; drop it onto another tile in the same area to change order. Undo and Redo continue to reflect the editor history state.

The three user-referenced styles are **Neon Glass**, **Soft Charcoal**, and **Cloud White**, using the central `Palette` already applied to keys and tool panels. `ThemePicker` now draws the complete keyboard at thumbnail scale in two columns and shows an Apply control. The existing themes and local JSON theme import remain available. The Enter face is a consistent arrow; editor action dispatch remains governed by `EditorPolicy` and the receiving field.

`ClipboardHistory` stores text with Android Keystore AES-GCM. Six newest unpinned clips are Recent; displaced or eight-hour-old entries appear in Old, up to twenty visible. All unpinned entries expire 24 hours after their original copy timestamp. Pins stay until individually deleted, explicitly cleared in the Pinned section, or the app is removed. The clipboard panel provides paste, Copy, Pin/Unpin, Delete, and Clear all for each section. The suggestion strip shows the current copied text when enabled. Sensitive Android clipboard flags, password/private fields and URI payloads are excluded from saved text history. Text clips are limited to 8,192 characters. If secure storage is temporarily unavailable, current-session copies remain usable but are not claimed to be saved across a restart.

Android limits clipboard access outside the active keyboard; copies made while the IME is closed cannot be guaranteed to appear in history. On reopening, the then-current system clipboard may be captured. Phone-specific clipboard behavior, Android keyboard-picker appearance, and perceived drag/hold feel require device acceptance.

Validation: `testDebugUnitTest`, `lintDebug`, and `assembleDebug` pass on the cloud Android 35/JDK 17 environment. Focused Robolectric tests cover six-to-seven clip rollover, eight-hour and twenty-four-hour ageing, encrypted pinned persistence and deletion, tool moves/reorder persistence, 2.5-second and five-second holds, and the arrow Enter face. Existing tests cover typing, Space cursor slide, voice, AI panel routes, themes, editor actions, and layout bounds. Native theme screenshots are generated under `/workspace/artifacts/ui-0.7.1` by the reference theme tests. No physical OPPO interaction test was available in the cloud environment.
